# Full transitive lock — every package pip actually installs for the
# direct dependencies in requirements.in.txt, not just the direct ones.
#
# This used to be a hand-pruned list of only the direct dependencies above,
# despite the regenerate instructions saying `pip freeze` — a real
# `pip freeze` produces ~57 lines (this file), not ~11, because it also
# captures every transitive dependency (starlette, anyio, httpcore,
# greenlet, google-auth, protobuf, ...). Leaving those unpinned meant a
# fresh `pip install -r requirements.txt` was never actually guaranteed to
# reproduce the exact environment this app was tested against, despite the
# top-level packages themselves being exact-pinned.
#
# Regenerate with, from a clean virtualenv:
#   pip install -r requirements.in.txt
#   pip freeze > requirements.txt
# then re-add this header comment and re-run the full test suite before
# committing — a mechanical freeze doesn't know which combination of
# versions is one you've actually verified.
#
# Test-only dependencies (pytest, respx) live in requirements-dev.txt, not
# here — this file is installed into the production Docker image
# (backend/Dockerfile), which has no reason to ship a test framework.
